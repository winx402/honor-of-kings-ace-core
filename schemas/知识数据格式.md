# 知识数据格式

知识内容版本为 `0.2.0`，领域模型版本为 `0.5.0`，两者独立。

目录包采用 `entries`，实体详细目录采用 `条目` 与 `数量`。记录的 `id` 是项目标识，不是官方API标识或官方英文名。英雄、棋手、英雄牌、技能和局内单位分别标识，同名不合并。

`scope_id` 引用适用范围；`game_version: null` 表示游戏版本未指定。没有效果说明字段表示本版未详述，并不表示该对象没有效果。`unknowns` 或 `未知项` 表示规则语义尚未确定的部分。

英雄初始面板中的攻速按每秒攻击频率记，暴击率按百分数记，攻击距离按格记。单位法力与棋手能量分别记录。技能伤害表达式是对应能力的名义值，不直接表示最终扣血。

关系中的 `source_id`、`target_id` 是关系起点与终点，不是资料来源。`source_revision_id`、`target_revision_id` 的 `null` 表示端点游戏修订未指定；知识版本由目录包规定。关系类型见[关系目录](../docs/architecture/relations.json)。

`rule_fact` 为规则知识，`strategy_advice` 为打法建议。阵容中的推荐装备、棋手、天赋和英雄位不表示局内已穿戴或强制组合；推荐的条件与实际能力限制仍适用。

`mechanism_hypothesis` 表示未确认的机制归属候选，不能作为规则事实或完整选择池使用。`strategic_inference` 表示从已知条件推导的运营理解，与建议及统计分别记录。

衍生目录中的棋手能力、模块、单位载体与分支不是一概可购买或可打出的手牌；`kind` 定义其内容角色。`definition_ref` 使秘技、奖励牌等既有标识指向同一机制的详细定义，同名不同分支仍分别保存。
